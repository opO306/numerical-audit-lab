## 핵심 측정: 어떤 궤도에서 몇 step까지 인증되는가

| | 규칙 궤도 (p = (1/4, 1/8), E = 0.039) | 혼돈 궤도 (p = (1/2, 1/4), E = 0.156) |
|---|---|---|
| 분류 (계획 3절 규칙) | 쌍둥이 분리 1.0×10⁻⁷ → 규칙 | 1.28 → 혼돈 |
| **규칙 V1 상태 인증 한계** | **1,779 step** (t ≈ 27.8) | **1,474 step** (t ≈ 23.0) |
| 상한: step 100 / 1,000 / 10,000 | 2.5×10⁻¹⁵ / 6.8×10⁻⁸ / ∞ | 5.7×10⁻¹⁵ / 1.3×10⁻⁵ / ∞ |
| (사후 추정, 상한 아님) 실제 오차: step 1,000 / 10⁴ / 5×10⁴ / 10⁵ | 3×10⁻¹⁶ / 8×10⁻¹⁵ / 5×10⁻¹⁵ / **1.7×10⁻¹³** | 2×10⁻¹⁴ / 1×10⁻⁷ / **0.84** / 0.64 |
| K1 시간 역전 (L = 100 / 10³ / 10⁴ / 10⁵) | PASS / REFUSED / REFUSED / REFUSED | PASS / REFUSED / REFUSED / REFUSED |
| (참고) K1 실제 잔차 L = 10⁵ | 4.7×10⁻¹³ | 0.83 |

**해석**

1. **규칙 V1이 인증하는 범위는 두 궤도에서 거의 같다(약 1,500–1,800 step).**
   - 원인은 궤도의 성질이 아니라 **상한을 계산하는 방식**이다.
   - 성분별 절댓값으로 오차를 전파하면, 원래 회전에 가까운 Verlet의 오차 동역학이 매 step 약 1.019배씩 커지는 것으로 바뀐다.
   - 1.019¹⁰⁰⁰ ≈ 10⁸이고, 실측과 일치한다.
2. **실제 오차는 두 궤도에서 완전히 다르다** (120자리 mpmath로 같은 프로그램을 돌린 사후 추정이며 상한은 아니다).
   - 규칙 궤도: 10⁵ step 뒤에도 약 10⁻¹³
   - 혼돈 궤도: 5×10⁴ step 무렵 O(1)까지 커진다. 반올림 오차가 혼돈으로 증폭된 것이다.
   - 즉 **진짜로 의미 있는 인증 범위는 궤도마다 자릿수가 다를 텐데, V1은 그 차이를 보지 못한다.**
   - 규칙 궤도에서 V1의 상한은 실제 오차보다 step 1,000에서 이미 약 2억 배 크다.
3. 시간 역전의 실제 잔차가 이 차이를 그대로 보여 준다(규칙 4.7×10⁻¹³, 혼돈 0.83). 하지만 상한이 무한대라 규칙상 **판정은 REFUSED**다.
   잔차를 인증된 결과처럼 쓰지 않는다.

## 전 구간(10⁵ step)에서 유지된 검사들

궤적 전체를 인증하는 상한이 무너진 뒤에도, **국소·구조 검사는 10⁵ step 내내 판정력을 유지했다.**

| 검사 | 규칙 궤도 | 혼돈 궤도 |
|---|---|---|
| N1 전수 감사 (전진·역진·거울 실행의 모든 binary64 연산) | 10,266,300개 중 잘못 반올림 **0** | 10,266,300개 중 **0** |
| K3 국소 힘 법칙 (매 step, 힘 4개) | 400,000회 중 실패 **0** | 400,000회 중 **0** |
| K5 독립 host-float 구현과 비트 동일 | 불일치 step **0** | **0** |
| K4 정확 구간 재실행 (8 step × 3, SAMPLED) | 상한 위반 **0** | **0** |
| K2 거울 대칭 | 기록 지점 7/7에서 비트 단위로 정확한 거울상. 판정은 step 10⁴부터 상한 ∞라 REFUSED | 같음 |
| M1 에너지 (2종) | REFUSED (방법 오차 상한 없음). \|ΔH\| ≤ 2×10⁻⁶ | REFUSED. \|ΔH\| ≤ 1×10⁻⁵ |

- 에너지 변화(10⁻⁶ 수준)는 반올림 몫 상한(step 100에서 10⁻¹⁵ 수준)보다 훨씬 크다. **에너지 변화의 거의 전부가 방법 오차(층 B)이고, 반올림이 아니다.** 두 층을 섞지 않아야 하는 이유가 숫자로 보인다.
- K4의 "최대 실제/상한 = 1.000"은 상한이 실제 오차와 정확히 같은 경우가 있었다는 뜻이다(넘지는 않음).
  첫 step처럼 전파할 오차 없이 국소 반올림 오차만 있을 때 정확 국소 오차를 그대로 쓰기 때문이다.

## 실행 중 발생한 구현 결함 (봉인 계획은 변경 없음)

1. **정확 구간의 숫자 문자열 한도.** 중간 지점의 binary64 상태에서 정확 산술을 8 step 하면 분자가 Python의 정수→문자열 변환 한도(4,300자리)를 넘었다. 정확 구간 함수 안에서만 한도를 풀었다.
2. **상한 ∞ 처리.**
   - ∞ × 0이 NaN이 되는 문제를 고쳤다(NaN을 ∞로 처리).
   - 에너지 반올림 몫 계산이 ∞를 분수로 바꾸려다 첫 전체 실행이 중단됐다. 상한이 ∞이면 반올림 몫도 ∞로 처리한다. 판정에는 영향이 없다(에너지는 원래 REFUSED).
3. JSON 보고서는 무한대를 `Infinity`로 적는다. Python은 읽을 수 있지만 엄격한 JSON 표준은 아니다.
