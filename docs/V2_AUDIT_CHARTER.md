# V2 오차 상한 독립 감사: 감사 범위 문서 (봉인)

- **감사 대상:** V2 시제품 (계획 `4f443da`, 구현 `3b8d445`, 결과 `84cf884`). 클라우드와 집 PC의 digest가 `6b5a39dc…16f7b`로 같다.
- **동결:** V2 파일은 이 문서와 함께 해시로 고정한다(`tests/test_v2_sealed.py`). **감사 중 V2 구현을 고치지 않는다.**
- **승격 조건:** 이 감사가 PASS여야 `BINARY64_TOLERANCE_RULE_V2`로 승격한다.
- **결함이 발견되면:** 현재 V2 결과는 그대로 보존한다. 수정판은 V2.1처럼 **별도 버전**(새 파일, 새 계획 봉인, 새 실행)으로 만든다.
- **선행 조건:** Gate 2B는 이 감사가 끝날 때까지 시작하지 않는다.

## 1. 독립성 요건

- **감사자는 V2 구현자가 아니어야 한다.** 구현자(이 세션의 Claude)는 감사자가 될 수 없다.
  구현자가 스스로 찾은 의심 지점은 4절에 공개했지만, 이것은 감사가 아니다.
- 권장: 다른 계열의 AI 모델이나 사람. 같은 모델의 새 세션은 독립성이 약하므로 보고서에 그렇게 표시한다.
- **감사자 코드의 독립성:** 감사자가 쓰는 검사 코드는 `lab/v2_bound.py`를 import하지 않고 따로 작성한다.
  비교를 위해 V2를 **실행**하는 것은 허용한다.
- **AI 감사자의 증거 기준:** AI가 "맞습니다"라고만 한 판단은 증거 0점이다(Lab 원칙). 각 판정에는 유도 과정이나 실행 가능한 반례·시험이 붙어야 한다.

| ID | 내용 | 구현자 판단 | 감사자에게 요청 |
|---|---|---|---|
| **F-SELF-1** | `v2_bound.py` 68행 `box = up(abs(xv) * b.box) + up(abs(yv) * a.box)`. 두 위로 반올림 값의 **합 자체는 위로 반올림하지 않는다.** 이 줄만 보면 합이 실제 합보다 최대 ½ulp 작을 수 있다 | 69행의 다음 `up(box + X)`(X ≥ 0)가 보상한다고 본다. 근거: s = fl(p+q) ≥ p+q − ½ulp(s). t = fl(s+X) ≥ s이므로 ulp(t) ≥ ulp(s)이고, 따라서 up(t) ≥ t + ½ulp(t) ≥ p+q+X. **우연한 보상에 의존하므로 설계 결함이다.** 수정판에서 명시적으로 위로 반올림해야 한다 | 이 보상 논증이 모든 경우(binade 경계, 부정규수, X = 0)에 성립하는지 판정. 성립하지 않는 반례가 있으면 **치명** |

## 5. 권장 공격 (감사자가 고르거나 더한다)

1. **독립 재유도:** P4·P5·P8·P9의 부등식을 처음부터 다시 유도한다.
2. **경계값 공격:** binade 경계, 부정규수, 0, 아주 큰 값, 부호가 섞인 계수에서 `_lin`·`_mul`·`rebase`가 실제 오차를 포함하는지 정확 유리수로 확인한다. 꼭짓점과 내부 점을 모두 본다.
3. **독립 상한 구현:** V2를 import하지 않는 별도 구현(예: mpmath 구간 산술 재실행이나 독립 affine 구현)과 결과를 비교한다.
4. **긴 정확 구간:** 정수→문자열 한도를 풀고, 8 step보다 긴 정확 산술 구간(예: 12 step)에서 실제 오차 ≤ V2 상한을 확인한다.
5. **결함 주입:** V2 코드 사본에 일부러 결함(예: 68행의 `up` 하나 제거, MUL 계수 매핑 뒤바꿈, ρ 생략)을 넣고 기존 시험(V2-S1/S2)이 그것을 잡는지 본다. 못 잡는다면 시험의 맹점이다.
6. **F-SELF-1 반례 탐색:** 68–69행의 보상이 깨지는 입력을 찾는다.

## 6. 감사 결과 형식과 판정 규칙

- 발견 사항마다 다음을 적는다:
  - ID
  - 심각도
    - **치명**: 상한이 실제 오차보다 작아질 수 있음
    - **주요**: 엄밀성 논증에 구멍이 있으나 반례 없음
    - **경미**: 조임·문서·비용 문제
  - 근거: 유도 또는 실행 가능한 반례
  - 재현 방법
- **감사 PASS:** 치명 0, 주요 0, P1–P15 모두 PASS(UNRESOLVED 0).
- **감사 CONDITIONAL:** 치명 0, 주요 1개 이상 또는 UNRESOLVED 있음. 승격하지 않고 V2.1에서 해결한다.
- **감사 FAIL:** 치명 1개 이상. 현재 V2 결과는 보존하되 "건전성 미보장"으로 표시하고, V2.1을 만든다.
- 구현자는 감사 결과에 반박할 수 있다. 다만 반박도 유도나 실행 가능한 근거여야 하며, 최종 판단은 설계자가 한다.
