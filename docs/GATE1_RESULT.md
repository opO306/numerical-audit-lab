## 질문에 대한 답

> 하나의 물리 결과를 서로 다른 관점에서 검사하면 실제로 추가 오류 탐지 능력이 생기는가?

**정답(참조 계산)이 없을 때는 "예", 정답이 있을 때는 "입력을 늘려 주는 만큼만"이다.**

### 1. 정답이 없을 때 (현실 문제, Gate 2 상황): 여러 관점이 필요하다

- 정답을 쓰지 않는 검사 9개를 합치면 7개 버그를 **모두** 잡는다.
- 하지만 **검사 하나로 7개를 다 잡는 경우는 없다.**
  - 가장 강한 것은 C4b(에너지 보고)와 C9(시간 역전)로, 각각 6/7이다.
  - 7개를 다 덮으려면 최소 2개가 필요하다. 가능한 조합은 7가지다. 예: C9+C10, C4b+C6, C5+C9
- 사람들이 보통 하는 **보존 법칙 검사는 약하다.**
  - 운동량(C3)은 2/7만 잡는다.
  - 특히 **M5(절대좌표 의존)는 모든 시나리오에서 운동량·에너지 보존을 둘 다 완벽히 통과하면서 틀린 답을 낸다.**
    잘못된 방향의 법선으로 "올바른 탄성충돌"을 하기 때문이다.
  - 이 버그는 평행이동(C6), 입자 교환(C5), 성질 검사(C10)만 잡는다.
- 따라서 "보존 법칙이 맞으니 시뮬레이션이 맞다"는 흔한 판단은 이 문제에서 **틀린 결론을 낼 수 있다.** 보존 법칙과 기하 불변성은 서로 다른 실패를 잡는다.

### 2. 정답이 있을 때: 변환 검사는 "새 입력 생성기" 역할을 한다

- 참조 계산(C1·C2)이 놓친 경우가 7건 있었다. 버그가 **그 특정 입력에서는 올바른 코드와 똑같은 출력**을 냈기 때문이다(equivalent on input).

  | 버그 / 시나리오 | 왜 같아졌나 | 잡은 검사 |
  |---|---|---|
  | M4, M6 / S1 | S1에서 우연히 v₂·d = 0 → v₁·d = (v₁−v₂)·d | C5, C8, C9 |
  | M4, M6 / S5 | v₂ = 0 | C5, C8, C9 |
  | M5 / S2, S5 | r₁ = 원점 → r₂ = r₂ − r₁ | C5, C6 |
  | M3 / S5 | d = (1,1) → x/y를 바꿔도 같음 | C7 |

- 이 7건은 모두 변환 검사가 입력을 바꿨기 때문에 잡혔다.
- **사후 대조:** 참조 계산 C1에 같은 변환 입력을 넣어 주면 7건 모두 C1도 잡는다.
  이 분석은 봉인 계획에 없던 것이며, 결과를 본 뒤 추가했다고 명시한다.
- 그러므로 정답이 있을 때 다관점 검사의 이득은 **새로운 수학이 아니라 입력의 다양성**이다.
  이것을 "다관점의 고유한 탐지력"으로 홍보하면 과장이다.

### 3. 어떤 입력에서도 잡을 수 없는 경우가 있다

- 같은 질량 시나리오(S2, S3)에서 M2(질량 계수 오류)와 M7(KE 오류)은 올바른 코드와 **모든 변환 입력에서까지 똑같다.**
- 어떤 검사로도 잡을 수 없으므로, 이 둘은 4/6이 최대다.
- **시나리오 설계(질량이 다른 경우를 포함하는가)가 검사 개수만큼 중요하다.**

### 4. 수치 층과 물리 층은 서로를 대신하지 못한다

- binary64 단계 반올림 감사(N1)는 논리 버그 7개를 **하나도** 잡지 못했다(0/42). 버그가 있어도 각 연산의 반올림은 올바르기 때문이다.
- 반대로 반올림 결함 R1은 N1이 5/6 잡았다. S2는 모든 값이 작은 정수라 버림과 반올림이 같아서 놓쳤다.
- 올바른 프로그램을 binary64로 돌려 정확 등식 물리 검사에 넣으면, S1에서 9개 중 7개가 경보를 냈다.
  **binary64 결과에 물리 검사를 쓰려면 허용 오차를 정해야 한다.** 이것은 아직 정하지 않았다(Gate 2 과제).

## 봉인 예측과 다른 칸 12개 — 원인

| 개수 | 칸 | 원인 |
|---|---|---|
| 11 | S1의 M4·M6 (C1, C2, C3, C4, C4b, C10 등) | 내가 S1을 설계할 때 v₂·d = 0인 것을 몰랐다. 그래서 두 버그가 S1 원래 입력에서는 올바른 코드와 같아졌다. 시나리오는 봉인되어 있으므로 고치지 않았다 |
| 1 | S1의 M2 × C9 | 예측할 때 C9가 속도뿐 아니라 KE′도 비교한다는 점을 빼먹었다. 속도는 정확히 되돌아오지만, M2는 에너지를 보존하지 않아 KE′가 다르다 |

S2의 예측 88칸은 모두 맞았다. 그중에는 "M5는 교환 검사에서 0으로 나누기로 멈춘다"는 예측도 있다.

## 봉인 해석 규칙에 따른 판정

| 규칙 | 결과 |
|---|---|
| M0에서 경보가 나면 해석 중단 | 경보 0건 → 해석 진행 |
| 정답 없는 검사 하나가 S1에서 7개를 다 잡으면 "이득 작음" | 하나로는 불가능 (S1에서 최대: C9가 6개) |
| 버그마다 잡는 검사가 다르고 합쳐야 다 잡히면 "추가 탐지 능력 있음" | **해당.** 최소 2개 조합이 필요하고 조합이 7가지 |

→ **정답이 없는 조건에서는 여러 관점의 검사가 추가 탐지 능력을 준다는 증거 1건(이 문제, 이 버그들)**.
정답이 있는 조건에서는 그 이득이 입력 다양성으로 설명된다.

## 한계

- 버그 7개는 손으로 고른 것이다. 실제 버그 분포를 대표하지 않는다.
- 문제가 하나이고, 충돌 한 번만 다룬다. 충돌 시각 계산, 여러 번의 충돌, 긴 시간 적분은 없다.
- 예측·구현·해석을 모두 같은 구현자가 했다.
