# Gate 1 — Physics Multi-Angle Verification: 계획 (봉인)

이 문서와 `benchmarks/gate1/predictions.json`은 **충돌 코드·검사 코드를 쓰기 전에** 커밋한다.
결과를 본 뒤 이 문서를 고치지 않는다. 바꿔야 하면 V2를 만들고 이유를 남긴다.

## 질문

> 하나의 물리 결과를 서로 다른 물리적·수학적 관점에서 검사하면, 실제로 추가적인 오류 탐지 능력이 생기는가?

이 Gate의 결과물은 "모든 시험 PASS"가 아니다. **어떤 종류의 버그를 어떤 독립 검사가 잡는지 보여 주는 표(mapping)**다.

## 물리 문제: 2D 두 원판의 완전탄성충돌 (마찰 없음)

- 입력: 질량 m₁, m₂, 접촉 순간의 중심 위치 r₁, r₂, 충돌 전 속도 v₁, v₂ (모두 유리수)
- 출력: 충돌 후 속도 v₁′, v₂′와 충돌 후 운동에너지 KE′ (5개 값)
- 공식: d = r₂ − r₁, k = ((v₁−v₂)·d)/(d·d), v₁′ = v₁ − (2m₂/M)k d, v₂′ = v₂ + (2m₁/M)k d (M = m₁+m₂)
- **sin·cos·√가 필요 없다.** 법선을 단위벡터로 만들지 않고 d·d로 나누기 때문이다. 그래서 정확한 유리수 계산이 가능하다.
- 접촉 거리(반지름 합)는 |d|²으로만 쓰고, 계산식에는 들어가지 않는다. 충돌 시각을 구하는 이차방정식은 다루지 않는다.

## 검사 대상(SUT)

`numeric_core` VM 프로그램으로 쓴 충돌 계산기다. 버그(mutant)는 이 프로그램에 심는다.
- 검사표의 모든 판정은 **EXACT 프로필** 실행 결과로 한다. 정확한 등식으로 비교하므로 허용 오차 문제가 없다.
- binary64 실행은 수치 층(N1) 확인용이다.

## 검사 11개 + 수치 층 1개 (각각 따로 쓴 코드)

| ID | 검사 | 정답을 직접 계산하나 | 쓰는 정보 |
|---|---|---|---|

- C3·C4·C10은 각각 운동량·에너지·접촉 조건을 본다. C3+C10을 합치면 답이 하나로 정해지지만, 각 검사는 따로 판정한다.
- 변환 검사(C5–C9)는 SUT끼리만 비교한다. C8의 KE 관계식만 입력 질량을 쓴다.
- SUT가 멈추면(예: 0으로 나누기) 그 검사는 "탐지(SUT 멈춤)"로 기록한다. 올바른 입력에서 멈추는 것도 결함이기 때문이다.

## 심는 버그 7개 (+ 기준 M0)

| ID | 버그 | 정확한 변경 |
|---|---|---|
| M0 | 없음 (기준) | — |
| M1 | 충격량 부호 반전 | v₁′ = v₁ **+** a₁d, v₂′ = v₂ **−** a₂d |
| M2 | 질량 계수 오류 | c₁ = 2m**₁**/M, c₂ = 2m**₂**/M (서로 바뀜) |
| M3 | x/y 축 혼동 | (v₁−v₂)·d 대신 rvx·**dy** + rvy·**dx** |
| M4 | 입자 1/2 비대칭 | 입자 2만 k 대신 (v₁·d)/(d·d) 사용 (상대속도가 아닌 v₁) |
| M5 | 절대좌표 의존 | d = r₂ − r₁ 대신 d = **r₂** (원점 기준 위치) |
| M6 | 갈릴레이 boost 의존 | 두 입자 모두 (v₁−v₂)·d 대신 **v₁**·d 사용 |
| M7 | 운동에너지 계산 오류 | KE′ = ½·m**₁**·(\|v₁′\|² + \|v₂′\|²) (두 입자 모두 m₁) |

수치 층 비교용으로 **R1**(binary64 반올림을 버림으로 바꾼 반올림 결함)도 하나 둔다. 이 결함은 binary64 실행에만 적용한다.

## 측정하는 것

1. **표:** 버그(M0–M7) × 검사(C1–C10, C4b) × 시나리오(S1–S6)마다 탐지 여부
2. **특이도:** M0에서 어떤 검사도 경보를 내면 안 된다. 경보가 나면 그 검사가 고장이다
3. **정답 없이 잡히는가:** 참조 계산(C1, C2)은 모든 버그를 잡는다. 현실 문제에는 정답이 없는 경우가 많으므로, 핵심은 **정답을 쓰지 않는 검사들(C3–C10, C4b)이 각 버그를 잡는가**다
4. **겹침:** 검사 하나가 모든 버그를 잡으면, 여러 각도로 검사해서 얻는 이득은 작다. 버그마다 잡는 검사가 다르면 이득이 있다
5. **수치 층:** N1이 논리 버그(M1–M7)를 잡는지, 반올림 결함(R1)을 잡는지
6. **봉인한 예측과 실측의 차이:** 다른 칸은 숨기지 않고 원인을 적는다

예측의 요점:
- S2에서 M2·M7은 같은 질량이라 **올바른 코드와 출력이 똑같다**(equivalent mutant). 이 시나리오에서는 어떤 검사로도 잡을 수 없다.
- M5는 r₁ = 원점이면 올바른 코드와 같아진다. 위치를 움직이는 검사(C6 이동, C5 교환)만 잡는다. C5에서는 d = 0이 되어 0으로 나누기로 멈출 것으로 예측한다.

binary64 기준(M0) 실행을 정확한 등식 검사에 넣으면 경보가 날 것이다. 이것은 버그가 아니라 허용 오차가 정의되지 않았기 때문이다.
그래서 Gate 1 V1에서 물리 검사는 EXACT 실행에만 적용한다.

## 이 Gate를 어떻게 해석하나 (미리 정함)

- **M0에서 경보가 하나라도 나면** 그 검사를 고치기 전에는 표를 해석하지 않는다.
- **정답 없는 검사들 중 하나가 S1에서 7개 버그를 모두 잡으면**, 이 문제에서 "여러 각도"의 추가 이득은 작다고 결론 낸다.
- **버그마다 잡는 정답 없는 검사가 서로 다르고, 그것들을 합쳐야 7개가 다 잡히면**, 여러 각도 검사가 추가 탐지 능력을 준다는 증거로 기록한다.
- Gate 2로 갈지는 이 표와 비용을 보고 설계자가 정한다.

## 한계 (미리 공개)

- 버그 7개는 설계자가 고른 종류를 구현자가 구체화한 것이다. 실제 코드에서 생기는 버그 분포를 대표하지 않는다.
- 예측과 버그 구현을 같은 사람(구현자)이 했다.
- 충돌 시각 계산(이차방정식, √ 필요)과 여러 번의 충돌은 다루지 않는다.
