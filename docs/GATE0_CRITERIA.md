# Gate 0 — Numeric Core Self-Test: 합격 기준 (봉인)

이 문서는 **벤치마크 코드를 쓰기 전에** 커밋한다. 결과를 본 뒤 이 기준을 고치지 않는다.
고쳐야 하면 새 판(V2)을 만들고, 이 V1과 왜 바뀌었는지를 함께 남긴다.

## Gate 0이 무엇인가

장비 검사다. 홍보물이 아니다.
복사해 온 계산기(`numeric_core/`)와 독립 채점기(`independent_checker/`)가 **제대로 작동하는지**만 본다.
Gate 0 통과는 "우리 물리 검증 체계가 특별하다"는 증거가 **아니다**. 숫자 시험을 잘 본 것뿐이다.

## 벤치마크 (V1에서 확정한 것)

| # | 이름 | 정답(oracle) |
|---|---|---|
| 1 | Rump의 catastrophic-cancellation 예제, f(a,b) = 333.75 b⁶ + a²(11a²b² − b⁶ − 121b⁴ − 2) + 5.5 b⁸ + a/(2b), a=77617, b=33096 | 문헌값 −54767/66192 |
| 2 | Muller 점화식 x₀=4, x₁=4.25, xₙ₊₁ = 108 − (815 − 1500/xₙ₋₁)/xₙ, n=30까지 | 닫힌 식 xₙ = (3ⁿ⁺¹+5ⁿ⁺¹)/(3ⁿ+5ⁿ) |
| 3 | canonical summation 또는 dot-product 벤치마크 | **미선정.** 출처와 정답을 원문으로 확인할 수 있는 것만 넣는다. 확인 전에는 Gate 0을 통과로 판정하지 않는다 |

정답은 한 가지 방법만으로 정하지 않는다. 벤치마크마다 서로 다른 세 가지 방법을 쓴다.
- 문헌값 또는 닫힌 식
- VM과 별개로 직접 쓴 정확 분수 계산
- mpmath 고정밀 계산

세 방법이 서로 맞지 않으면 채점기는 답을 고르지 않고 `REFUSED`를 낸다.

## 합격 조건 (전부 만족해야 Gate 0 PASS)

| ID | 조건 | 판정 방법 |
|---|---|---|
| G0-1 | 알려진 수치 함정을 모두 탐지 | 일반 binary64로 계산한 최종값을 "올바르게 반올림된 정답"이라고 주장시키면 채점기가 `INVALID`를 낸다 |
| G0-2 | exact/reference 정답 재현 | VM의 EXACT 프로필 결과가 oracle과 정확히 같다 |
| G0-3 | 독립 checker가 올바른 결과를 accept | oracle을 올바르게 반올림한 값은 `VALID`. VM binary64의 **각 단계** 연산 결과도 독립 판정기가 전부 accept |
| G0-4 | 의도적으로 넣은 오답을 reject | 다음을 넣으면 **전부** 거부해야 한다. 최종값 ±1 ulp, EXACT 결과 + 아주 작은 오차, 각 단계 결과 ±1 ulp, 서로 맞지 않는 oracle(이 경우는 `REFUSED`) |
| G0-5 | A 코드를 import하지 않고 독립 실행 | 정적 import 검사 + 실행 후 `sys.modules`에 A 모듈(`a_numeric`, `engine`, `audit`, `a_reference`, `c1b1_replay` 등)이 없음 |
| G0-6 | Vast 없이 로컬 PC에서 전부 완주 | 설계자의 집 PC에서 `python run_gate0.py`가 끝까지 실행됨. **클라우드 컨테이너 실행은 이 조건을 대신하지 않는다** |
| G0-7 | 비용 기록 | wall-clock, Python 힙 peak(tracemalloc), 연산 수를 보고서에 남긴다. **합격 기준이 아니라 기록만 한다** |

`원 계산 대비 N배 이내` 같은 비율 기준은 쓰지 않는다(설계자 결정). 짧은 계산에서는 비율이 의미를 잃기 때문이다.

## 판정 어휘

- `VALID` — 주장된 값이 정답과 맞다(binary64/FX는 정답을 올바르게 반올림한 값, EXACT는 정확히 같은 값)
- `INVALID` — 값을 주장했는데 틀렸다
- `REFUSED` — 판정하지 않는다(실행기가 멈춰서 값이 없음, oracle끼리 불일치 등). 실패도 통과도 아니다

## 이 봉인의 한계 (숨기지 않음)

- 기준을 쓴 사람(구현 에이전트)과 벤치마크를 만들 사람이 같다.
  Rump와 Muller는 결과가 널리 알려져 있으므로, 이 봉인이 결과를 모르는 상태를 보장하지는 않는다.
  봉인의 목적은 **결과를 보고 기준을 바꾸는 일**을 막는 것이다.
- 봉인은 로컬 git 커밋이다. 외부 타임스탬프가 아니다.
