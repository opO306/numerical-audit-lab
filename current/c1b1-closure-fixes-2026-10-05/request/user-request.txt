# 1. F-CLOSURE-1 수정

현재 B3가 future drift guard를 다음처럼 요구하고 있습니다.

```text
exact unrounded segment 전체 검사
+
stored rounded segment 전체 검사
```

그러나 기존 독립 감사 PASS를 받은 Arithmetic V1의 실제 계약은:

```text
exact unrounded closed segment minimum >= r_min²

AND

stored final relative position squared >= r_min²
```

입니다.

즉 두 번째 검사는 stored segment 전체 minimum이 아니라 **stored 최종 상대 위치 한 점**입니다.

B3 규범을 기존 Arithmetic V1 의미로 되돌리십시오.

정식 규범은 다음으로 고정하십시오.

```text
Point admission:

    exact current R² >= r_min²


After drift:

    minimum over the exact unrounded closed relative segment
        >= r_min²

    AND

    stored final relative position squared
        >= r_min²
```

다음 조건은 이번 V1 규범에서 제거하십시오.

```text
minimum over the stored rounded segment >= r_min²
```

그 검사를 정말 추가하고 싶다면 기존 Arithmetic guard와 별개의 **새로운 더 강한 정책**으로 따로 설계·감사해야 합니다.

이번 closure 수정에서 추가 guard를 새로 구현하지 마십시오.

현재 `proof-wire.json`에는 Failure schema에 대해 서로 충돌하는 두 closed field 목록이 있습니다.

```text

status
phase
reason
resource_kind
spec_sha256
state_sha256
occurrence_sha256
budget_sha256
attempt_count
attempt_digest
```

`resource_kind`는 **항상 존재하는 필수 field**로 유지하십시오.

규칙:

```text
resource-related failure:
    resource_kind = 정의된 enum

non-resource failure:
    resource_kind = null
```

따라서 `resource_failure_record`의 `closed fixed fields only` 목록에도 반드시:

```text
resource_kind
```

를 추가하십시오.

서로 다른 두 closed 목록이나 암묵적 precedence를 남기지 마십시오.

# 9. B5 상태는 변경하지 말 것

이번 FAIL은 numeric budget 숫자가 없어서 발생한 것이 아닙니다.

B5 상태는:

```text
METHOD SPEC PASS
RUNTIME NUMERIC INSTANCE STILL REQUIRED BEFORE ACTIVATION
```

으로 유지하십시오.

근거 없이 budget 숫자를 새로 발급하지 마십시오.

Impulse implementation 전에도 method closure와 runtime activation은 별개입니다.

후속 실제 실행 전에는 여전히:

```text
numeric instance hash
independent activation decision
source/platform/allocator-bound majorants
whole-call preflight
isolated worker memory/CPU/wall enforcement
```

가 필요합니다.

이번 F-CLOSURE 수정 범위에 이것을 억지로 끼워 넣지 마십시오.
