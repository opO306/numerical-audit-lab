# 2. Independent Impulse의 목적

새 독립 계산기는 원본 executor가 계산한 `J`를 받아 검산하는 것이 아닙니다.

목표는:

> 주어진 C1-B1 상태와 frozen physical/numeric specification으로부터 impulse `J` 자체를 독립적으로 계산하고, 원본 executor가 사용한 `J`와 비교할 수 있는 별도 oracle을 만드는 것

입니다.

따라서 최종적으로 원하는 구조는:

```text
Frozen C1-B1 state/spec
          │
          ├── Original executor impulse
          │
          └── Independent impulse oracle
                       │
                       ↓
                 J comparison
                       │
                       ↓
          Audited Arithmetic V1
             K → D → K / guards
```

입니다.

```text
a_reference/c1b1_fast_impulse.py
a_reference/c1b1_impulse_primitives.py

또 다음도 금지합니다.

원본 함수 호출
원본 helper import
FunctionType rebinding
AST function extraction
source copy 후 exec
monkeypatch로 원본 계산 우회 호출
원본 fast path를 expected answer generator로 사용
```

원본 소스는 **비교 대상**이지 independent oracle이 아닙니다.

# 4. 먼저 specification source를 식별

Independent Impulse V1을 구현하려면 어떤 수학적 정의가 authoritative한지 먼저 고정해야 합니다.

설계 문서에서 최소 다음 항목의 출처를 찾아 표로 정리하십시오.

```text
physical potential V(R)
dV/dR 또는 force definition
radial direction / q vector convention
impulse sign convention
half-step / full-step time factor
mass dependence 여부
unit system
R definition
R=0 또는 domain-invalid handling
exp / inverse / power semantics
rounding 위치
interval/enclosure 의미
precision escalation
refusal / STOP 조건
J를 momentum grid로 변환하는 정확한 계약
```

각 항목마다:

```text
source document
section
adopted meaning
frozen / candidate / unresolved
```

를 기록하십시오.

원본 구현에서 “그렇게 하고 있으니 specification”이라고 역으로 정의하지 마십시오.

# 5. 물리식과 수치 실행 계약을 분리

# 6. 독립 oracle은 처음부터 fast일 필요 없음

첫 버전의 목표는 속도가 아닙니다.

우선:

```text
impulse_exact_reference
```

를 가장 단순하고 감사하기 쉬운 방식으로 설계하십시오.

가능한 구조 예:

```text
physical inputs
↓
exact / high-precision independent primitive evaluation
↓
independent force / impulse construction
↓
certified interval or exact rounding decision
↓
J_raw or REFUSED/UNPROVED
```

원본 Candidate B의 최적화 구조를 따라갈 필요가 없습니다.

속도 최적화는 independent slow oracle이 검증된 뒤 별도 단계입니다.

# 9. Independent primitive 문제를 따로 다룰 것

Impulse에서 가장 위험한 부분은 단순 add/sub보다:

```text
sqrt
inverse R
powers
exp
potential derivative
interval direction
```

같은 비선형 primitive입니다.

따라서 설계서에서 각각:

```text
어떻게 계산할 것인가
무엇이 exact인가
무엇이 interval인가
어떻게 enclosure를 증명하는가
host float를 사용하는가
rounding direction을 어떻게 보장하는가
```

를 분리해서 기술하십시오.

“Python Decimal/mpmath를 쓰면 고정밀이므로 충분” 같은 설명은 허용하지 마십시오.

고정밀과 정확한 enclosure는 다른 주장입니다.

# 10. 기존 exact checker / Point Prover와 관계 조사

현재 프로젝트에는 이미 exact checker와 Point Prover 계열의 자산이 있습니다.

Independent Impulse V1 설계 시:

```text
기존 자산을 재사용하면 독립성이 깨지는 부분
공유 가능한 specification/data
별도 oracle로 사용 가능한 것
동일 구현 계통이라 oracle로 사용하면 안 되는 것
```

을 구분하십시오.

특히 원본 executor의 impulse implementation과 코드 계보가 같은 도구를 independent oracle이라고 부르면 안 됩니다.
